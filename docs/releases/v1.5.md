# Kaiju v1.5: Kobe is now Kaiju

Release notes for the people who run Kaiju. v1.5 renames the product from Kobe to Kaiju. It adds
no new feature and changes no behavior except the names. Your data, sessions and Workspaces stay.
The design and the owner's decisions are in [docs/specs/rename-kaiju.md](../specs/rename-kaiju.md).

You upgrade in place. There is no side-by-side install of the old and new names: replace the
running release with `helm upgrade` and your values unchanged ([Upgrade steps](#upgrade-steps)).

The member and admin view is the guide's [What's new](../guide/whats-new.md) page (served at
`/docs/whats-new`). The per-change detail for operators is in the install guide's
[Upgrade notes](../install.md#upgrade-notes). This page links there instead of repeating it.

**Before you upgrade:** take a `kaiju backup`. Four migrations (`0260` to `0263`, as numbered when
these notes were written) rewrite stored names, and they cannot be undone by going back a release.

## What changed for members

- **The name.** The app, its emails, the sign-in page, the guide and `/llms.txt` say Kaiju. A
  site that set its own name under **Site admin, Appearance** keeps it.
- **Cookies and storage.** Browser cookies and storage keys have new names. Each browser forgets
  its own choices once: theme, last Workspace and conversation, panel sizes and tabs, and notices
  members closed. Sessions are kept. An SSO sign-in in progress during the upgrade must be started
  again.
- **Built-in names.** The built-in connectors are `kaiju` and `kaiju-git`, so their tools are
  `mcp__kaiju__...` and `mcp__kaiju_git__...`. The built-in agent is **Kaiju**, and the built-in
  skill `kobe-guide` is `kaiju-guide`. Rules, remembered approvals and agent tool lists move
  with them. An approval that was waiting for an answer during the upgrade ends; members send the
  message again.
- **Git branches.** New pull request branches are named `kaiju/<member>/...`. Branches made
  before the upgrade keep their `kobe/` names and keep working until merged or closed.
- **Build line in the guide.** The guide page shows the running build next to its title, for
  example `Build 1e6fff80abcd, 2026-11-24 14:03 UTC`, or "Development build" (KOBE-837).
- **Email subjects.** Subjects and bodies that named the product now use the Site's app name
  (KOBE-834). The sign-in app name and the passkey and authenticator labels stay "Kaiju".
- **Connect button for OAuth connectors.** My connectors lists OAuth connectors with Connect,
  Reconnect and Disconnect, and the Site console can connect an admin's own account to pin tools
  (KOBE-835). It ships in this release.

## What changed for operators

Each item links to the detail in the install guide.

- **Chart and images.** The chart is `charts/kaiju` (`oci://ghcr.io/splittingatom/charts/kaiju`)
  and the images are `ghcr.io/splittingatom/kaiju-*`. No values key changed. If you mirror images,
  mirror the new repositories first. [Details](../install.md#upgrade-notes).
- **Environment variables.** Settings are `KAIJU_*`. For this release every service, the
  migration Job and the `kaiju` CLI also read the old `KOBE_*` name when the new one is unset,
  and log one warning that names it. Rename what you set by hand, in scripts and in CI.
  [Mapping](../install.md#environment-variable-names-kaiju_).
- **Headers, telemetry and service names.** Send the Workspace as `X-Kaiju-Team`. The server
  still accepts `X-Kobe-Team` for this release. Internal headers go out under both names.
  Log `service` fields, Postgres `application_name`, span and attribute names, `service.name`
  and the audit forwarding's syslog and OTLP names start with `kaiju`. Update SIEM rules,
  saved queries and dashboards. [Postgres connections](../install.md#postgres-connections),
  [Tracing](../tracing.md#names-after-the-rename-to-kaiju), [Audit log](../audit-log.md).
- **Team namespace prefix.** New value `sandbox.teamNamespacePrefix`. An existing install keeps
  `kobe-team-` (the chart detects it from the team namespaces), so sandboxes, volumes and quotas
  are untouched. A fresh install uses `kaiju-team-`. If you render offline (`helm template`,
  Argo CD, Flux), set `kobe-team-` in your values first. [Sandboxes](../install.md#sandboxes).
- **Sandbox users and paths.** The Unix users are `kaiju`, `kaiju-agent`, `kaiju-pi-<n>` and
  `kaiju-tool-<n>`, with the same numeric ids, so file owners do not change. The home is
  `/home/kaiju`, and `/home/kobe` is a link to it. Paths in the images moved to `/opt/kaiju` and
  `/run/kaiju-*`.
- **The `.kaiju/` workspace folder.** A sandbox moves `/workspace/.kobe/` to `.kaiju/` when it
  starts on the new image, in one rename and before anything else runs. If both folders hold data,
  the agent keeps both and the server logs a warning. If the move fails, the pod restarts and
  retries; after two failed restarts the wake fails with an audit event, and nothing is deleted.
  [Resolve it and roll back](../install.md#upgrade-notes) (see "The sandbox folder").
- **Local model ids.** The in-cluster models are `kaiju-local/...` (the embedding model is
  `kaiju-local/nomic-embed-text`).
- **The repository.** The repository is `SplittingAtom/kaiju`. GitHub redirects the old URL.
  Update clones, CI and any pinned links.

### Migrations 0260 to 0263

- **0260, built-in connector.** Renames connector `kobe` to `kaiju` and `kobe-git` to `kaiju-git`,
  with their fixed ids. Rewrites tool names in site and team rules, remembered approvals, team
  exposure lists and agent drafts and versions. Moves the settings `kobe_mcp.*` to `kaiju_mcp.*`.
  Approvals still waiting for an answer end.
- **0261, local models.** Rewrites the stored `kobe-local/...` model ids to `kaiju-local/...`: the
  Site embedding model, the model recorded on every memory vector (nothing is embedded again) and
  Orbit evals that have not run. The append-only usage ledger keeps the old ids; reports count
  both as one model.
- **0262, stored values.** Renames the catalog publisher value `kobe` to `kaiju`, rewrites
  Kaiju-published provenance and the scanner name, and moves the gallery agent's key and slug to
  `kaiju`. The gallery agent is published as **Kaiju** unless a site admin customized it.
- **0263, guide skill.** Renames the catalog skill `kobe-guide` to `kaiju-guide` in place (same
  id, pins and access kept) and updates the reserved-name check.

Each migration logs a notice in the migration Job for every conflict it resolves
(`kubectl logs -f job/<release>-migrate`).

## What stays `kobe`

These names are internal, or hold data that outside files still carry. They do not change.

- Ticket ids (`KOBE-n`) and the Hadron project key.
- Postgres settings, roles and functions: `kobe.team_id` and the other `kobe.*` settings,
  `kobe_app`, `kobe_owner`, the `kobe_*` functions, and the database name `kobe`.
- Kubernetes label keys `kobe.splittingatom.io/*`, the chart's pod label
  `app.kubernetes.io/name: kobe`, and the Bifrost customer, provider and key names.
- Persisted schema ids: `kobe.dev/*` in skill packages and exports, `kobe.approval.v1` in signed
  approvals.
- The backup format (`kobe-backup/1`), so old backups still restore. See
  [backup-restore.md](../backup-restore.md).
- Older release notes, gate documents, ledgers and earlier specs, which keep the name they were
  written under.
- Audit rows, the usage ledger and run history, which are append-only.

## Upgrade steps

1. Take a backup: `kaiju backup` (or `kobe backup` from the old CLI). Keep copies of your Secrets
   ([backup-restore.md](../backup-restore.md#secrets)). A backup from before the rename restores
   with this release's `kaiju restore`.
2. Rename the `KOBE_*` variables you set by hand, in scripts and in CI. The old names still work
   for this release.
3. If you render the chart offline, set `sandbox.teamNamespacePrefix: kobe-team-`.
4. Run `helm upgrade <release> charts/kaiju -n <namespace> -f <your values> --reset-values`.
   Use your release name and unchanged values. Nothing is recreated.
5. Follow the migration Job's log until it succeeds.
6. **Do not change the Site memory settings during the roll.** Saved through an old pod, they
   would embed every memory again. Wait until every server pod runs the new release.
7. Update SIEM rules, dashboards, log filters and `pg_stat_activity` queries for the new names.

While the pods roll, old pods briefly miss the renamed connector, gallery agent and `kobe-guide`
skill: runs there get no Kaiju or git tools for those minutes, and nothing is allowed that should
not be. The [Upgrade notes](../install.md#upgrade-notes) list each effect.

## Rolling back

Migrations `0260` to `0263` are not reversible, and an older release does not read the new names.
To go back, restore the `kaiju backup` from step 1 onto the older release
([backup-restore.md](../backup-restore.md#restore-onto-a-fresh-cluster)). A sandbox-image-only
rollback is possible but the sandbox then reports a folder conflict when it returns
([details](../install.md#upgrade-notes)). Do not run older images under this chart.

## Removed in the next release

The next release removes every one-release fallback. Rename and update before you upgrade to it.

- The `KOBE_*` environment fallback and its startup warning.
- `X-Kobe-Team`, the internal headers under both names, the old response headers (the skill
  export hash and the workspace file entry), the old run header names in the sandbox model
  extension and the old span attribute mapping.
- The old skill-scan result marker (rebuild any custom scanner image).
- The Orbit eval gateway route `/kobe/eval-cases`, the pack id `kobe-default` and the
  `/run/kobe-skills` folder.
- The old built-in connector paths and fields: `/v1/team/connectors/kobe`, a catalog skill's
  `/kobe/compare` and `/kobe/reset`, the MCP proxy's `/internal/v1/mcp/kobe/*`, the site settings
  fields `kobeMcpMode`, `kobeReadsPerMinute` and `kobeWritesPerHour`, and the readers of the
  `kobe_mcp.*` settings keys. Any value left in an old key is moved to the new one first.
- The `kobe-local` provider alias the gateway sync keeps in Bifrost.
- The reader of the old "What Kobe knows" memory headers in the context viewer.
- The `kobe.model_error:` prefix and the `kaiju_names` capability bridge.

**Kept permanently** (old-name readers, because stored or downloaded data still holds them):

- Deny and ask rules written under the old tool names keep matching (never allow rules).
- Reading `kobe.skill.yaml` and `compatibility.kobe` in skills, and `metadata.kobe` in Orbit
  export files.
- Pi sessions recorded under the old provider id and entry types, and the refusal of the `.kobe`
  folder name as agent-internal.
- Published agent versions with the old internal tool value, read as `kaiju`.
- The usage ledger's old model ids, counted with the new ones.
- The reserved names `kobe`, `kobe-git` and `kobe-guide`.
- MCP Apps old names (`io.kobe/item-kind`, `kobe/notifications/drag-*`) until Catalyst sends the
  new ones. This is a separate ticket and does not depend on the release.
